## Project: Ricardo's Portfolio Enhancements

- **Date:** 2026-03-23
- **Project Path:** `/projects/ricardomboukou`

### Summary of Work

This session focused on significantly enhancing the project management features of Ricardo's portfolio dashboard. We implemented two major features, fixed several bugs, and improved the overall architecture and user experience.

### Key Features Implemented

1.  **AI-Powered Project Creation:**
    - **Goal:** Allow creating a new portfolio project by analyzing an existing GitHub repository.
    - **Technology:** Switched from an initial OpenAI plan to the **Google Gemini API**.
    - **Workflow:**
        - User provides a GitHub URL in the new "Analyze" UI.
        - A new API route (`/api/admin/projects/analyze-repo`) securely calls the GitHub API to fetch the `README.md` and `package.json`.
        - The extracted content is sent to the Gemini API with a detailed prompt.
        - The AI returns a structured JSON object (`title`, `slug`, `description`, `technologies`).
        - The project form in the dashboard is automatically pre-filled with this data.

2.  **Image Uploads with Cloudinary:**
    - **Goal:** Provide a way to upload and host project images securely and efficiently.
    - **Technology:** Chose **Cloudinary** for its robust free tier, CDN, and automatic optimization capabilities.
    - **Workflow:**
        - Added a file input field to the project modal.
        - Created a secure API route (`/api/admin/upload-image`) that handles the upload process.
        - The frontend sends the file to this route, which then securely uploads it to Cloudinary, keeping API secrets server-side.
        - The returned Cloudinary URL is used to populate the "Image URL" field in the form.

### Bug Fixes & Refinements

- **Authentication:** Resolved a recurring `401 Unauthorized` error by adding `credentials: 'include'` to all `fetch` calls made to protected API routes. This ensures the authentication cookie is always sent.
- **Data Caching:** Fixed a bug where deleted projects remained visible on public pages by using Next.js's `revalidatePath` to invalidate the cache after database mutations.
- **Image Configuration:** Updated `next.config.ts` to whitelist the Cloudinary hostname (`res.cloudinary.com`), fixing errors related to the `next/image` component.
- **Error Handling:** Improved error handling in API routes to provide more descriptive feedback to the user, which was crucial for debugging API key and model name issues.
- **UI/UX:** Replaced native browser `alert()`s with `react-hot-toast` notifications for a better user experience.
- **Code Quality:** Refactored the `ProjectModal` out of the main dashboard page and into its own component for better organization and maintainability.
